# Arad AI — نسخه ۲.۰

رابط گفتگوی هوش مصنوعی با چند مدل، انتخاب مدل در نوار چت و دکمهٔ **Thinking** —
ساخته‌شده تنها با **HTML، CSS و JavaScript**. بدون فریم‌ورک، بدون npm، بدون CDN.

---

## ۱) شروع در سه گام

### گام ۱ — کلید سرویس را بگذارید
فایل `assets/js/config.js` را باز کنید و در بخش `PROVIDERS` کلید هر سرویسی که استفاده می‌کنید را وارد کنید:

```js
var PROVIDERS = {
  openai:   { baseUrl: 'https://api.openai.com/v1',   apiKey: 'sk-...' },
  deepseek: { baseUrl: 'https://api.deepseek.com/v1', apiKey: 'sk-...' },
  local:    { baseUrl: 'http://localhost:11434/v1',   apiKey: '' }
};
```

### گام ۲ — مدل‌های دلخواه را تعریف کنید
در همان فایل، آرایهٔ `MODELS` را ببینید. هر مدلی که می‌خواهید در منوی برنامه دیده شود، یک شیء است:

```js
{
  id: 'arad-fast',                 // شناسهٔ یکتا و ثابت
  name: 'Arad Fast',               // نامی که کاربر می‌بیند
  model: 'gpt-4o-mini',            // نام دقیق مدل برای API
  provider: 'openai',              // ارجاع به PROVIDERS
  description: 'سبک و پرسرعت برای گفتگوهای روزمره',
  badge: 'سریع',
  vision: true,                    // تصویر می‌پذیرد؟
  thinkingMode: 'prompt',          // حالت Thinking (پایین توضیح داده شده)
  temperature: 0.7,
  maxTokens: 4096
}
```

### گام ۳ — اجرا
`index.html` را در مرورگر باز کنید. همین.

> اگر مرورگر روی `file://` محدودیت داشت:
> ```bash
> cd arad-ai
> python3 -m http.server 8000
> # http://localhost:8000
> ```

**کاربر نهایی هیچ تنظیماتی برای API نمی‌بیند.** نه کلیدی، نه آدرسی، نه صفحهٔ تنظیمات.
او فقط مدل را از نوار چت انتخاب می‌کند.

```

├── README.md
├── CHANGELOG.md

    │   └── app.css         ← چیدمان، گفتگو، منوی مدل، مارک‌داون
    └── js/
        ├── config.js       ← ★ سرویس‌ها و مدل‌ها (تنها فایل قابل ویرایش)
        ├── utils.js        ← DOM، ذخیره‌سازی، پردازش تصویر
        ├── markdown.js     ← رندر مارک‌داون + هایلایت کد
        ├── api.js          ← ارتباط، پارسر SSE، حالت Thinking

| فایل | مسئولیت |
|---|---|
| `config.js` | `PROVIDERS` (آدرس/کلید)، `MODELS` (فهرست مدل‌ها)، پیش‌فرض‌ها، `Config.models()` / `Config.resolve()` |
| `utils.js` | `$`، `el()`، ذخیره‌سازی، فشرده‌سازی تصویر، کلیپ‌بورد، زمان |
| `markdown.js` | مارک‌داون به HTML + رنگ‌آمیزی ۲۰+ زبان |
| `api.js` | ساخت درخواست بر اساس مدل انتخابی، استریم SSE، Thinking، خطاها |
| `ui.js` | حباب پیام، منوی مدل، اعلان، پنجره، نمایشگر تصویر |
| `app.js` | چرخهٔ گفتگو، سوئیچ مدل، کلید Thinking، پوسته/زبان |

## ۳) سوئیچ مدل در نوار چت

در پایین کادر نوشتن، چیپی به نام مدل فعلی هست. با کلیک روی آن منوی مدل‌ها باز می‌شود:

- **هیچ درخواستی برای کشف مدل‌ها ارسال نمی‌شود.** فهرست دقیقاً همان چیزی است که در `config.js` نوشته‌اید.
- انتخاب هر مدل بلافاصله ذخیره می‌شود و در پیام بعدی استفاده می‌گردد.
- هر پیام نام مدلی را که تولیدش کرده در سربرگ خود نگه می‌دارد.
- اگر مدلی `vision: false` باشد، دکمهٔ پیوست تصویر خودکار غیرفعال می‌شود.
- مدل‌ها با `↑`/`↓` و `Enter` هم قابل انتخاب‌اند.

نمونهٔ افزودن یک مدل تازه:

```js
{
  id: 'arad-groq',
  name: 'Arad Turbo',
  model: 'llama-3.3-70b-versatile',
  provider: 'groq',
  description: 'پاسخ‌های بسیار سریع',
  badge: 'توربو',
  vision: false,
  thinkingMode: 'off',
  temperature: 0.6,
  maxTokens: 4096
}
```

## ۴) دکمهٔ Thinking

در نوار چت، کنار پیوست، دکمهٔ **Thinking** با وضعیت روشن/خاموش است. این دکمه فقط وقتی فعال می‌شود که مدل انتخابی از آن پشتیبانی کند. رفتار آن با `thinkingMode` در `config.js` تعیین می‌شود:

| `thinkingMode` | کاری که انجام می‌شود | مناسب برای |
|---|---|---|
| `'effort'` | ارسال `reasoning_effort: 'medium'` (قابل تنظیم با `thinkingLevel`) | مدل‌های استدلالی مثل `o4-mini` |
| `'budget'` | ارسال `thinking: { type: 'enabled', budget_tokens: N }` | سرویس‌های سازگار با Anthropic/OpenRouter |
| `'prompt'` | افزودن یک دستور استدلال به پرامپت سیستمی | مدل‌های عادی که فیلد استدلال ندارند |
| `'off'` | دکمه غیرفعال می‌شود | مدل‌های کوچک محلی |

وقتی Thinking روشن است و مدل متن استدلال (`reasoning_content`) برمی‌گرداند، آن متن در بخش تاشوی «فرایند استدلال» بالای پاسخ نمایش داده می‌شود. وضعیت دکمه در مرورگر ذخیره می‌شود.

## ۵) ویژگی‌ها

**گفتگو**
- استریم کلمه‌به‌کلمه با پارسر SSE مقاوم به شکست مرزها
- **اسکرول یک‌پله‌ای:** با رسیدن پیام تازه، صفحه فقط به اندازهٔ همان پیام پایین می‌آید؛ پیام قبلی بالای کادر می‌ماند و هیچ پیامی پنهان یا حذف نمی‌شود. اگر پیام از پنجره بلندتر باشد، ابتدای آن بالای کادر می‌نشیند.
- **دنبال‌کردن هوشمند:** تا وقتی کاربر پایین کادر است، متن در حال تولید دنبال می‌شود؛ به‌محض اسکرول به بالا، رها می‌شود.
- توقف تولید (`Esc`) با حفظ متن تولیدشده
- تلاش مجدد، کپی و حذف پیام
- چند گفتگو با ذخیرهٔ خودکار، جستجو، تغییر نام، حذف
- نمایش مصرف توکن و نام مدل هر پاسخ

**رندر محتوا**
- مارک‌داون کامل: عنوان، پررنگ/ایتالیک/خط‌خورده، فهرست تودرتو، نقل‌قول، جدول، پیوند، تصویر
- بلوک کد با رنگ‌آمیزی، برچسب زبان، کپی و شکست خط
- رندر درست بلوک کدِ ناتمام در میانهٔ استریم
- خنثی‌سازی HTML ورودی (بدون اجرای اسکریپت تزریقی)

**تصویر**
- پیوست با دکمه، `Ctrl+V` یا کشیدن و رها کردن
- فشرده‌سازی خودکار روی Canvas
- نمایشگر تمام‌صفحه

**رابط**
- پوستهٔ تاریک/روشن/هم‌سان با سیستم
- فارسی (RTL) و English (LTR) با چرخش کامل چیدمان
- **کاملاً واکنش‌گرا:** دسکتاپ، تبلت و موبایل با نوار کناری کشویی، دکمه‌های اندازهٔ لمس، احترام به `safe-area` و هماهنگی با کیبورد موبایل
- دسترسی‌پذیری: ARIA، پیمایش با کیبورد، احترام به `prefers-reduced-motion`

### موبایل

| نکته | رفتار |
|---|---|
| ارتفاع صفحه | از `visualViewport` خوانده می‌شود؛ با باز شدن کیبورد، کادر نوشتن بالای آن می‌ماند |
| نوار کناری | کشویی از کنار صفحه، با پردهٔ تاریک و دکمهٔ بستن |
| منوی مدل | برگهٔ تمام‌عرض بالای نوار چت (الگوی رایج موبایل) |
| دکمه‌های پیام | روی دستگاه لمسی همیشه دیده می‌شوند (hover وجود ندارد) |
| اندازهٔ فونت ورودی | ۱۶px تا مرورگرهای موبایل هنگام فوکوس بزرگ‌نمایی نکنند |
| صفحه‌های باریک | زیر ۴۰۰px برچسب Thinking جمع می‌شود و نام مدل کوتاه می‌شود |
| گوشی افقی | چیدمان فشرده با پیشنهادهای دوستونی |

## ۷) نکتهٔ امنیتی (مهم)

کلیدها در `config.js` داخل بستهٔ سمت کلاینت هستند. یعنی هر کسی که فایل‌ها را در اختیار داشته باشد می‌تواند آن‌ها را در DevTools ببیند — حتی اگر در رابط کاربری هیچ گزینه‌ای برای مشاهده یا ویرایششان وجود نداشته باشد.

- این کار برای استفادهٔ شخصی، فایل محلی یا ابزار داخلی تیم مناسب است.
- برای انتشار عمومی روی اینترنت، یک پروکسی کوچک سمت سرور بگذارید که کلید را نگه دارد و درخواست‌ها را به سرویس اصلی بفرستد؛ سپس در `config.js` آدرس همان پروکسی را در `baseUrl` قرار دهید.

برای استقرارهایی که نمی‌خواهند کلید داخل فایل باشد، تزریق در زمان اجرا هم پشتیبانی می‌شود:

```html
<script>window.Arad.Config.setProvider('openai', { apiKey: '...' });</script>
```

## ۸) رفع اشکال

| نشانه | راه‌حل |
|---|---|
| «این مدل هنوز پیکربندی نشده است» | `apiKey` آن `provider` را در `config.js` پر کنید. |
| `[401]` | کلید نامعتبر است؛ همان پیام راهنما را نشان می‌دهد. |
| `[404]` | `baseUrl` یا نام `model` اشتباه است. مسیر باید به `/chat/completions` برسد. |
| `[429]` | محدودیت نرخ؛ کمی بعد تلاش کنید یا مدل دیگری انتخاب کنید. |
| ارتباط برقرار نمی‌شود | آدرس سرویس و مجوز CORS آن را بررسی کنید؛ برنامه را روی سرور محلی اجرا کنید. |
| دکمهٔ Thinking خاکستری است | مدل انتخابی `thinkingMode: 'off'` دارد یا آن را پشتیبانی نمی‌کند. |
| دکمهٔ پیوست غیرفعال است | مدل انتخابی `vision: false` است. |
| فهرست گفتگوها پاک می‌شود | حافظهٔ مرورگر پر شده؛ از دکمهٔ خروجی پشتیبان بگیرید. |

## ۹) توسعه و آزمون

فضای نام `window.Arad` با این بخش‌ها: `Config` · `Utils` · `Markdown` · `API` · `UI` · `App`.

- مدل جدید → یک شیء در `MODELS`
- سرویس جدید → یک کلید در `PROVIDERS`
- زبان رنگ‌آمیزی جدید → ورودی در `RULES` و نام در `KNOWN` داخل `markdown.js`
- رشتهٔ رابط جدید → `STRINGS` در `ui.js`

### آزمون‌های این نسخه
- ۲۴ آزمون رندر مارک‌داون و هایلایت کد
- ۴۰ آزمون لایهٔ API: تفکیک مدل‌ها، ساخت درخواست، سه حالت Thinking، vision، پارسر SSE، `[DONE]`، خطاهای HTTP، لغو، عدم پیکربندی
- ۵۲ آزمون رفتار رابط روی DOM واقعی: حذف کامل تنظیمات، منوی مدل، Thinking، ارسال و استریم، رندر، ذخیره‌سازی، پوسته و زبان
- ۳۱ آزمون اسکرول و چیدمان: ریاضی اسکرول یک‌پله‌ای (پیام کوتاه/بلند/نیمه‌پیدا/بالاتر از کادر)، محدودشدن به انتها، و صحت قواعد موبایل
